# Acesso do FleetOps por Cloudflare Workers

Este diretório publica uma entrada em `workers.dev` na conta Cloudflare do proprietário. Ela encaminha o FleetOps para seu servidor Cloudflare Workers existente, gerenciado pelo Sites, e usa a mesma base D1 e as mesmas logos R2. A Vercel não participa desse caminho. Este projeto não transfere o banco, as logos ou os segredos anteriores para outra conta.

O Worker começa fechado. Depois de publicar, use a origem HTTPS exata retornada pela Cloudflare, sem barra final, como variável `PUBLIC_ORIGIN`. Configure uma credencial aleatória de pelo menos 48 bytes em `GATEWAY_TOKEN`, como segredo. Na instalação original, a mesma credencial deve estar no segredo `FLEETOPS_CLOUDFLARE_GATEWAY_TOKEN`, e a origem deve estar em `FLEETOPS_CLOUDFLARE_GATEWAY_ORIGIN`. Publique uma versão salva do Sites para aplicar essa configuração. A credencial da Vercel é independente e não deve ser alterada.

Publique este diretório com Wrangler; não publique a raiz do aplicativo como site estático. Use uma conta Cloudflare já autenticada e confirme que o nome `fleetops-smg1` está disponível antes de publicar para evitar sobrescrever outro Worker. Não escreva tokens em arquivos, argumentos de terminal, logs ou Git. `preview_urls` fica desativado e somente a origem exata de produção é aceita. O nome de conta que compõe o endereço só é conhecido depois do acesso à Cloudflare.

O encaminhamento preserva corpo, cookies, chaves de transportadora, origem do navegador e consultas. Cabeçalhos de identidade nativa e encaminhamento enviados pelo visitante são descartados; o IP vem do cabeçalho da plataforma Cloudflare. O servidor valida a credencial e o host antes de usar a origem para login, cookies, proteção de origem, links de e-mail e rate limits. Páginas e APIs não usam cache compartilhado. A recuperação nativa continua na instalação original; o login por e-mail usa o novo endereço. As sessões são independentes por domínio.

Validação local: `node scripts/check-cloudflare-gateway.mjs`, `node scripts/check-gateway.mjs`, build e `node scripts/check-worker.mjs`. Os testes usam base e e-mails simulados; não enviam pedidos ou mensagens reais. Antes da entrega, confira HTTPS, login, recursos estáticos, portais e retorno 403 das APIs sem credencial no endereço publicado. O funcionamento na rede corporativa depende da política da empresa.
