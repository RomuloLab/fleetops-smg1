# Acesso do FleetOps pela Vercel

Este projeto publica uma entrada HTTPS na Vercel e encaminha páginas, arquivos e APIs para o mesmo servidor do FleetOps. O banco D1, as logos em R2, as chaves de transportadora, o remetente e os registros continuam na instalação original. É uma alternativa de acesso, não uma transferência completa do servidor ou dos dados.

O projeto Vercel deve permanecer público, assim como a entrada original; as permissões de gestor e de transportadora continuam verificadas pelo FleetOps em cada operação. A variável secreta de produção `FLEETOPS_GATEWAY_TOKEN` deve ser igual à variável secreta de mesmo nome no Sites. Nunca escreva seu valor neste diretório. No Sites, `FLEETOPS_GATEWAY_ORIGINS` contém a lista explícita de origens HTTPS permitidas, separadas por vírgula e sem barra final. A configuração usa `https://fleetops-smg1.vercel.app,https://fleetops.dev.br`, mantendo os dois endereços disponíveis. Se a lista estiver ausente, `FLEETOPS_GATEWAY_ORIGIN` continua aceitando uma única origem para compatibilidade. `AUTH_BASE_URL`, `BETTER_AUTH_SECRET` e `LINK_SECRET` permanecem inalteradas.

A Vercel substitui o cabeçalho de autenticação da entrada usando a variável secreta. O Worker confere o segredo com comparação em tempo constante, a origem configurada, o host/protocolo encaminhados e o IP. Só então usa a origem pública para URLs, proteção de origem, cookies e links de código por e-mail. Identidade nativa do ChatGPT nunca é aceita através dessa entrada. A recuperação nativa do master abre o endereço original; o login por e-mail funciona no novo endereço. Sessões existentes não são copiadas entre domínios: entre uma vez no novo endereço.

Páginas e APIs encaminhadas não são armazenadas no cache compartilhado. O token da entrada não substitui a sessão ou a chave da transportadora, nem autoriza o visitante a ver outros dados. Ao sair da conta pela Vercel, a sessão é encerrada e a navegação retorna a `/login` nesse mesmo domínio. Requisições diretas à instalação original continuam com seu comportamento anterior. Nenhuma tabela ou migração é criada para essa entrada.

Publique somente o `vercel.json` deste diretório no projeto Vercel correspondente, sem enviar a raiz inteira do repositório. Configure o segredo antes de publicar. Verifique o domínio de produção retornado, configure as origens no Sites e publique o Worker atualizado. Confirme `X-FleetOps-Entry: vercel`, tela de login, arquivos, portais, verificação de origem e acesso autenticado. O teste na rede corporativa ainda precisa ser feito nessa rede.

O domínio próprio `fleetops.dev.br` está associado a este projeto Vercel e usa o DNS do Registro.br. O apontamento deve ser feito na zona existente com os registros recomendados pela Vercel para esse domínio, preservando MX, TXT e registros do Resend. A associação do domínio ao projeto não confirma propagação DNS ou emissão do certificado: confira a configuração e o HTTPS após o apontamento. O hostname `www` só funciona se for associado e configurado separadamente. Links de login usam o domínio validado de cada requisição; outro domínio da lista não pode enviar operações em seu lugar.
